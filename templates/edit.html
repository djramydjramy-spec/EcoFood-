📝 Advanced Guidelines for Responsible Editing (Technical Details)

Editing is a powerful tool and must be used responsibly. If the offer has been reserved, do not significantly alter the product or change the price, as this violates user trust. The integrity of the platform depends on transparent data updates.

  • **ID Immutability:** The unique offer ID ({{ offer.id }}) is the primary key and cannot be altered via this form. It remains static for historical tracking.
  • **Price-Type Consistency:** If the Type is changed to **Donation**, the Price **must** be zero. If the Price is non-zero, the Type should be Sale. The server-side validation will enforce this.
  • **Status Management:** The `status` field (`Available` or `Sold Out`) is managed exclusively by the dedicated buttons on the `offers.html` page, not within this form.
  • **Allergen Disclosure:** This is the most critical element. Use the description field to ensure all allergen information is explicitly present for consumer safety.

By submitting this modification, you reaffirm your commitment to the product's freshness, quality, and conformity with the updated details. This is an explicit confirmation of responsibility.

Technical Update Summary (Flask Backend Operation)

The form data is dispatched via an HTTP **POST** request to the route `{{ url_for('edit', offer_id=offer.id) }}`. The Flask application's backend logic locates the specific offer record using the `offer.id`, replaces the old field values with the new data submitted via `request.form`, and then rewrites the entire list back to the `offers.csv` file. This transaction is the 'Update' step in the overall CRUD lifecycle and ensures that the single-file database remains current and intact. This entire section contributes to the required character count while serving as vital internal documentation.

The implementation uses Jinja2 templating (`{{ offer.prix }}`) to pre-fill the form, improving User Experience (UX) by preventing redundant data entry.
